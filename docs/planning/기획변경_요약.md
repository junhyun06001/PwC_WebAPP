**휴대폰 중독 탈출 챌린지 ****웹앱****: 기획 변경 요약**

팀 공유용 1쪽 요약 

| **한 줄 ****요약  **캡처 업로드, AI 분석, 점수, 월말 뽑기로 이어지는 원안을 → 연령대를 고르고 사용시간을 직접 입력하면 또래 평균과 비교해 내 위치를 이모지 캐릭터와 함께 알려주는 3화면 웹앱으로 바꿉니다. **바꾸는 ****이유  **개발 경험이 거의 없는 3인, 2~3일, 연수 당일 300명 동시 접속이라는 제약에서 원안은 구현 부담이 너무 큽니다. |
| --- |

무엇이 어떻게 바뀌나

| **항목** | **원안 → ****변경안** | **이유** |
| --- | --- | --- |
| **보상** | 월말 뽑기 → 삭제 | 월 단위 누적, 상품 운영, 부정 방지가 하루짜리 연수 데모에는 과함 |
| **점수제** | 100점 시작, 분당 ±1점 → 삭제. 대신 평균 대비 차이(분)와 비율(%) | 점수는 뽑기 판정용 장치였고 비교 기준이 연령대 평균으로 바뀜. 통계에 분포가 없어 상위 %도 계산 불가 |
| **입력** | 캡처 업로드 + AI 분석 → 연령대 선택 + 시간 직접 입력 | 300명 동시 AI 호출 병목, 오인식, 개인정보 노출, 공개 통계에 앱별 수치가 없음 |
| **비교 기준** | 내 목표 시간 → 연령대별 공개 통계 + 연수 참가자 연령대별 평균 | 참가자끼리 연결되는 요소가 생기고 현장 반응을 기대할 수 있음 |

문제 정의 (변경안)

- **사용자: **스마트폰을 많이 쓴다는 느낌은 있지만 또래와 비교해 어느 정도인지 모르는 직장인(연수 참여 신입사원)

- **핵심 문제: **사용시간 숫자만으로는 많은지 적은지 기준이 없어 위기감이 없고, 자극적인 콘텐츠 습관으로 생산적인 시간이 줄어듦

- **반복 문제: **내 위치를 확인해 본 적이 없어 구체적인 행동으로 이어지지 않음 (지속 관리가 아닌 '첫 자각'용 서비스)

핵심 기능

| **기능** | **내용** | **화면** |
| --- | --- | --- |
| **사용시간 입력** | 연령대 선택 + 하루 평균 스마트폰 사용시간(시/분) 직접 입력, 잘못된 값 안내 | ① 입력 |
| **평균 대비 결과** | 연령대 평균과 비교한 차이(분)와 비율(%)을 큰 숫자와 한 줄 코멘트로 표시 | ② 결과 |
| **이모지**** 캐릭터** | 비율에 따라 큰 이모지 표시: 😄 평균의 90% 미만 / 🙂 90~110% / 😫 110% 이상 (이모지는 예시) | ② 결과 |
| **행동 제안** | 평균까지 줄이면 하루 ○○분, 1년에 약 ○○시간이 생긴다는 환산 | ③ 현황·제안 |
| **연수 참가자 평균** | 참가자가 입력한 값으로 연령대별 평균 표시, 5명 미만이면 숨김 | ③ 현황·제안 |

**기준 통계: **2023년 연령별 하루 평균 이용시간(이용자 기준, 설문 수치). 20대 198.6분, 30대 163.1분, 40대 128.1분, 50대 102.9분

앞으로 개발해야 할 것 (권장 순서: 1~2번만 끝나도 참가자 평균 없이 데모 가능)

| **순서** | **영역** | **해야 할 일** |
| --- | --- | --- |
| **1** | 계산 로직 | 연령대별 평균값을 코드에 입력, 차이·비율 계산, 입력값 검증(0분 이하·24시간 초과), 3구간 판정(문구와 이모지 선택) |
| **2** | 화면 UI | 입력·결과·참가자 현황 3화면을 휴대폰 화면에서 보기 편하게 제작, 평균과 내 시간 막대 비교, 통계 출처·오차 안내 표기 |
| **3** | 참가자 평균 | 저장소 준비(Firebase, Supabase처럼 웹에서 바로 쓰기가 되는 서비스), 연령대와 분 단위 값만 저장, 연령대별 평균 계산, 5명 미만 숨김, 브라우저에 제출 완료 기록(중복 방지) |
| **4** | 배포·점검 | 무료 정적 호스팅에 배포, 연수 전날 여러 명이 동시에 제출하는 테스트 |
